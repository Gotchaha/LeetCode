### Reviewed solution

```cpp
class Solution {
public:
    Node* copyRandomList(Node* head) {
        Node* it = head;
        if (it == nullptr) return nullptr;

        std::unordered_map<Node*, int> map;
        map[nullptr] = 0;
        int n = 1;
        while (it != nullptr){
            map[it] = n;

            n++;
            it = it->next;
        }

        std::vector<Node*> res(n);
        res[0] = nullptr;
        it = head;
        for (int i=1; i<n; i++){
            res[i] = new Node(it->val);
            it = it->next;
        }

        it = head;
        for (int i=1; i<n; i++){
            if (i == n-1) res[i]->next = nullptr;
            else res[i]->next = res[i+1];

            res[i]->random = res[map[it->random]];
            it = it->next;
        }

        return res[1];

    }
};
```

### Starting approach and reasoning

The solution represents the correspondence between original and copied nodes in two stages:

```text
original node pointer -> one-based index -> copied node pointer
```

The first traversal records each original node's position in an `unordered_map`. Index zero is reserved for `nullptr`. The second traversal allocates new nodes with the corresponding values and stores them in `res`. The third traversal assigns `next` through adjacent vector positions and assigns `random` by translating the original target through the map and vector.

This directly addresses the difficult part of the problem: a random pointer may target any node, including one appearing later in the list, so the complete correspondence is established before random edges are reconstructed.

### Correctness invariant

Let `N` be the number of input nodes. The code variable `n` equals `N + 1` after the first traversal because index zero is the null sentinel.

After the first traversal:

- `map[nullptr] == 0`.
- Every original node has a unique index from `1` through `N` in list order.

After the second traversal:

- `res[0] == nullptr`.
- For every index `i` from `1` through `N`, `res[i]` is a distinct newly allocated node whose value equals the value of original node `i`.
- These nodes are partial copies because their relationships have not yet been reconstructed.

After the third traversal has processed indices `1` through `i`:

- Every processed copied node has the correct value.
- Its `next` points to the copy of the original node's successor, or to `nullptr`.
- Its `random` points to the copy of the original node's random target, or to `nullptr`.

For an original node `X` with `X.random == Y`, `map[Y]` is the position of `Y`, and `res[map[Y]]` is the newly allocated copy of `Y`. Thus the copy of `X` points to the copy of `Y`, never to `Y`. When `Y == nullptr`, the sentinel chain is `nullptr -> 0 -> nullptr` through `map` and `res`.

All non-null pointer assignments in the returned structure select elements of `res`, and every non-null element of `res` was created with `new`. Therefore no returned pointer targets an original node. The original list is never modified.

### Complexity

- Expected time: `Theta(N)`, assuming expected constant-time `unordered_map` operations.
- Strict worst-case time: `O(N^2)` because hash-table operations may theoretically degenerate to linear time.
- Auxiliary space: `Theta(N)` for the `unordered_map` and vector.
- Required output space: `Theta(N)` for the copied nodes.

The map and vector each contain `N + 1` entries when the null sentinel is included; this does not change the asymptotic bound.

### Strengths

- Correctly separates node creation from edge reconstruction.
- Handles null, self-referential, forward, and backward random pointers.
- Uses pointer identity, so duplicate values cause no ambiguity.
- Does not mutate the original list.
- Makes the deep-copy property straightforward to prove once the correspondence is explicit.

### Prioritized improvements

1. A direct `original pointer -> copied pointer` map would express the correspondence more directly and eliminate the one-based indices and sentinel vector slot. It remains expected `Theta(N)` time and `Theta(N)` auxiliary space; its main advantage is clarity, not guaranteed runtime improvement.
2. Names such as `indexByNode` and `copies` would reveal the state meaning more clearly than `map` and `res`. The code variable `n` is also one greater than the actual node count.
3. `map[it->random]` uses `unordered_map::operator[]`, which inserts a missing key with a default value. The official constraints make the key valid here, but `at()` would state the lookup invariant more explicitly.

### Alternative approaches and tradeoffs

#### Direct old-to-copy map

Create every copied node while storing `copyOf[original] = copy`, then reconstruct both edges through that mapping.

- Expected time: `Theta(N)`
- Strict worst-case time: `O(N^2)`
- Auxiliary space: `Theta(N)`
- Tradeoff: simpler correspondence and fewer conceptual passes, but not necessarily a smaller runtime constant because both pointer fields require hash lookups.

#### Interleaving

Temporarily insert each copied node immediately after its original node. The copy corresponding to original node `X` is then available as `X->next`. If `X.random == Y`, the copied random target is `Y->next`. After setting random pointers, separate the interleaved structure into the restored original list and the copied list.

- Strict worst-case time: `Theta(N)` across three linear traversals
- Auxiliary space: `Theta(1)`, excluding the required output nodes
- Output space: `Theta(N)`
- Tradeoff: removes the map and its degeneration risk, but temporarily mutates the input and requires more delicate pointer restoration.

Interleaving is worst-case time-optimal because creating and initializing `N` output nodes already requires `Omega(N)` work.

### Related lessons

- A useful cloning pattern is: establish a vertex correspondence, create all destination vertices, and then reconstruct edges through the correspondence.
- The same proof structure applies to graph cloning and trees containing arbitrary cross-references.
- `unordered_map` provides expected constant-time operations, not a strict constant-time guarantee.
- `unordered_map::operator[]` performs lookup plus possible insertion; `at()` performs a checked lookup without insertion.
- Auxiliary-space analysis normally excludes required output storage. If output is included, every valid solution here uses `Theta(N)` total new memory.

### Feynman explanation and refinement

The initial explanation correctly identified the map as a relation table between original nodes and copies, described the three passes, and derived expected `Theta(N)` time, strict `O(N^2)` worst-case time, and `Theta(N)` auxiliary space. It also correctly identified interleaving as a strict `Theta(N)`-time, `Theta(1)`-auxiliary-space alternative.

The first explanation of the deep-copy property stated that avoiding original pointers was a requirement rather than proving that the implementation met it. The refinement traced the actual expression `res[map[it->random]]`: the inner lookup obtains the original target's stable index, and the outer vector access selects its newly allocated counterpart. The null case was handled through the zero sentinel.

The refined loop invariant states that, after processing indices `1` through `i`, every processed copied node has the correct value and both outgoing pointers target the correct copied counterparts or `nullptr`. A processed node may point to a copied node whose own fields have not yet been processed, but that pointer's identity is already correct.

Another clarification distinguished mathematical list length `N` from the code variable `n`, which equals `N + 1` because of the sentinel.

### Final takeaway

The solution is a correct and interview-ready map-based clone. Its central proof is not merely that every value is copied, but that every edge is translated through a complete original-to-copy correspondence, so no output pointer can reach the original structure. Interleaving improves strict worst-case time and auxiliary space by storing that correspondence temporarily in the list itself, with greater implementation risk.
